Start here

Do the task once. Stop paying for it after that.

Lots of Mac work has no API — you click through an app because that is the only way in. An AI can do that clicking. But it re-reads the screen and decides again on every run, and you pay every time.

ONCE

You do the task

An AI drives it and EchoPath watches. This run is the slow, expensive one.

THEN

It keeps what worked

The order of actions, plus a small picture of each thing that got clicked.

AFTER

It replays, free

It follows the recording and asks the AI nothing, swapping in your new values.

One number matters: model calls. Each is a request to the AI — real money, 5–10 seconds. EchoPath's whole job is to make that number zero.

One sentence explains all five

Typed words replay perfectly. Clicked things replay only if they never move or change.

Clicking furniture — a search box, a sort menu, a form field — replays free. Clicking something that is the data goes wrong, and sometimes goes wrong silently: it clicks the old spot, hits nothing, and still says “done”.

Four kinds of target

Which one finds the click depends on what you are clicking

There are three ways to decide where a click goes, at very different prices. We ran four tasks that break them in different places — 60 scored runs, five fresh variations each.

Matches pixels

EchoPath's saved patch

Hunts for a small picture of what you clicked. Blind to anything that changed.

~50 ms · free

Reads words

Decision Model (Jev)

Reads the screen with Apple's Vision OCR, picks one line, and says how sure it is. Sees words. Nothing else.

~300 ms · $0.00005

Looks at a screenshot

The vision model

Sends the whole picture to a large AI. Handles most things — and is the call EchoPath exists to avoid.

~5 s · ~16,000 tokens

Jev is typesafe/jev-1.13, a System One model that returns a typed choice with probabilities instead of text. It cannot read a screen by itself, so we hand it one: screenshots go through Apple's Vision framework (VNRecognizeTextRequest), and the text lines it returns become Jev's options.

The same page, two targets, opposite winners

One row of a PubMed search result. Select it, or open it.

Same row. The blue target and the violet target have opposite winners.

Select it and the patch wins 5/5 for free: the checkbox looks identical on every query. Jev gets 0/5 — it reads the row perfectly, but it can only aim at text, and the control is not text.

Open it and that reverses. The title is different every query, so the patch cannot match it (0.49–0.62, under its 0.74 bar) and falls through to the expensive model. Jev gets 5/5, because the title is the link.

When the target has no words at all

Mute a video on Wikimedia Commons.

Violet = what OCR could read. The mute button has none, so it was never on Jev's list.

Jev scored 0/5 and its own confidence said so. It was asked to pick the mute control from a menu containing a clock. The patch scored 5/5, free — a toolbar never moves.

And where neither works

Open the diff for one revision in a Wikipedia page history.

Fourteen identical prev links. Only the dates tell them apart.

The patch matches at 0.98–1.00 — and clicks the wrong row. Because it is confident, it never asks for help. It does the wrong thing and reports success, which is worse than failing. Jev can name the right line, but OCR returns (cur | prev) as one blob, so it cannot aim at prev either. Everything scores 0.

The fix

Ask the cheap one first

Do not choose between them. Try them in order of price, and only pay the big model when both have given up.

The same moment, as each rung sees it. Rung one's saved patch is 52×52 pixels of the old page — you can read “man fil” from “Kalman filter”, which is why it cannot match this one.

The ladder finishes the most and costs the least — 15 of 20 against 14, for one three-hundredth of the price. It made no calls at all to the vision model where the patch alone made five, because Jev caught every miss first, at 0.70–0.90 confidence.

It does not fix the identical-controls case, and nothing here does. That column stays at 0, and it fails in the worst way: confidently, without asking for help.

Fit & limits

Does your workflow fit?

Two questions. Does it repeat often enough to earn back a first run that costs more? And what do its clicks land on?

Where this shape of work lives

WorkflowWhat repeats Why no API
Legacy ERP entrySAP GUI, Oracle Forms Purchase orders, journal entries — dozens daily Integration licences cost six figures
Insurance claims intake Re-keying from PDF into a claims system Thick clients predate REST
SaaS admin consoles Onboarding one person across 10–15 tools No bulk user API below enterprise tier
Regulatory & tax portals The same filing, monthly, per entity Session-based web UIs by design
Literature screening Select the same shape of result, hundreds at a time The selection is the judgement

These fit because they are form-shaped: varying values typed into fixed fields, and clicks that land on controls rather than on data.

What these numbers are, exactly

The patch measured here is a stand-in, not the shipping matcher. These runs use a single-scale greyscale template match at a 0.74 threshold. EchoPath's own visual_grounding.py sweeps scales from 0.5 to 2.0, offers edge and colour modes, rejects ambiguous matches, and uses 0.78. The identical-controls result in particular may improve in the real thing, because that ambiguity check exists to refuse exactly that match.

The ladder is not wired into the product. It was measured in a standalone harness; EchoPath's replay path still goes straight from the patch to the vision model.

What we did tighten. The demonstrated variation is never scored, so no template is matched against the screenshot it was cut from. Success is read from the page's own state over DevTools Protocol, never from pixels — a pixel oracle would be template matching, the thing under test. And every task runs a negative control: a click proven to land on a different element must fail the check, or the task is reported as unscorable. That check caught three harness bugs that would otherwise have been published as findings.

Scale. Five variations per cell, one run each, one Mac, one session. Enough to show that these failure modes are real and disjoint; not enough to put a confidence interval on any single number.

Measured on one Mac (Darwin 25.5, Codex CLI bridge); model calls counted from each run's own event log. The without-EchoPath run was produced by moving its memory aside, then restoring it. Web tasks ran in a logged-out window at a fixed size on live pages — PubMed, Wikimedia Commons and Wikipedia — scored by page state, never by matching the text of the element chosen. All Wikipedia interaction was read-only: the targets are diff links, no account was used and nothing was edited. OCR is Apple's Vision framework; Jev is typesafe/jev-1.13 on OpenRouter. Vision cost is its token count priced at $3 per million. The five workflow failures are first attempts, no retry. Flight-search figures are the authors' own — single runs, not averages.
